# 5. Stages 00 and 01 — reading the slide, checking the image

Two quick stages before segmentation. Together they take a few minutes to
about half an hour depending on slide size.

- **Stage 00, ingest** — opens the `.qptiff`, records its size, pixel size,
  channel list, and a checksum so you can prove later which file was used.
- **Stage 01, image QC** — measures each channel, decides which parts of the
  image are tissue rather than empty glass, and saves that tissue mask.

Stage 02 cannot run without both.

## Submit

```bash
pipeline/sbatch_mail.sh --account=<GROUP> --qos=<GROUP> \
    pipeline/run_stages_00_01.slurm samples/my_slide.csv results
```

Reading that command:

| Part | Meaning |
|---|---|
| `pipeline/sbatch_mail.sh` | submits the job **and** makes sure it emails you |
| `--account=<GROUP> --qos=<GROUP>` | your SLURM account and QoS from page 1 |
| `pipeline/run_stages_00_01.slurm` | the job description |
| `samples/my_slide.csv` | **your** samples file |
| `results` | where output goes — becomes `results/<sample_id>/` |

It prints a job number, for example `job 12345678: email on END,FAIL...`.
Write the number down.

### Many slides, or very large ones

The job handles the slides in your samples file **one after another**, and it
has a **4-hour limit**. Stage 00 reads every byte of each slide to fingerprint
it, so a sheet of ten 30 GB slides can run out of time partway through. Two
ways round it:

- **Ask for more time** — add it before the job script:
  ```bash
  pipeline/sbatch_mail.sh --account=<GROUP> --qos=<GROUP> --time=12:00:00 \
      pipeline/run_stages_00_01.slurm samples/my_slide.csv results
  ```
- **One job per slide** — add `--sample-id <your-sample-id>` at the end and
  submit once per slide. A failure then only costs that slide.

Slides that finished before a timeout keep their results; resubmit only the
ones that are missing (check with `ls -d results/*/01_image_qc`).

## Watching it

```bash
squeue -u $USER
```

| `ST` column | Means |
|---|---|
| `PD` | pending — waiting for a free machine |
| `R` | running |
| (gone from the list) | finished, one way or another |

Waiting in `PD` for a while is normal. Do not resubmit.

To see the output as it happens:

```bash
tail -f logs/akoya_00_01_12345678.out
```

Replace the number with yours. `Ctrl`+`C` stops watching — it does **not** stop
the job.

---

## Did it work?

```bash
sacct -j 12345678 --format=JobID,State,Elapsed,MaxRSS
```

`COMPLETED` is what you want. Anything else — see page 11.

Then look at what appeared:

```bash
ls results/<your-sample-id>/00_ingest/ results/<your-sample-id>/01_image_qc/
```

You should see `ingest.json` and `channels.csv` from stage 00, and `qc.json`,
`channel_qc.csv`, `analysis_mask.npz` and `tissue_histograms.npz` from stage 01.

## Read the reports

Both stages write an HTML report:

```
results/<your-sample-id>/reports/00_ingest.html
results/<your-sample-id>/reports/01_image_qc.html
```

Copy them to your own computer to open in a browser. From a terminal **on your
laptop**:

```bash
scp -r <your-username>@<cluster-login-host>:/blue/<GROUP>/<USER>/akoya-pipeline/results/<your-sample-id>/reports ~/Desktop/
```

**Look at the QC report before going further.** Check that the channel names
match what you expect, that the tissue mask covers the tissue and not the
glass, and that your nuclear channel actually looks like nuclei. Segmentation
inherits every mistake here, and a bad tissue mask is much cheaper to fix now
than after a multi-hour segmentation run.
